# Agent Note: 可恢复的桌面用户操作

Status: implemented

[English](2026-08-24-recoverable-desktop-user-operations.md) | 中文

## 问题

多个桌面操作会跨过浏览器、Host、文件系统或提供方边界，但失败没有回到发起操作的人面前。启动失败时，无边框窗口可能没有恢复控制；Workspace 导航与侧边栏操作可能只在控制台里报错；设置可能在持久状态确认前看起来已经保存；DeepSeek 凭据可能在验证当前输入的密钥前就被写入；角色包设置只暴露文件夹，而不是一条安装流程。弹窗和菜单组件也把键盘焦点行为交给各个调用方处理。这些缺口会让拒绝看起来像点击无效或修改成功。

## 决策

Web 客户端尚不可用时，由桌面外壳负责本地化的恢复状态。加载页和失败页保留与主窗口相同的可拖动标题栏以及最小化、最大化和关闭控制；启动失败时提供重试、复制诊断信息和打开日志文件夹。Web 根组件对客户端启动失败采用相同的恢复方式：直接显示人能理解的摘要，并允许按需展开技术细节。

发起可逆用户操作的组件会保留进行中或失败状态，直到权威所有者确认成功，或用户主动重试。Lumi 偏好设置写入后会比较最终设置快照，拒绝时恢复先前值。角色包目录加载会区分加载中、旧数据回退、只读、目录被拒绝和可重试状态。窄窗口会禁用场景模式并说明原因，不再保留一个无法产生所标示结果的控件。

`WorkspaceRuntime` 会把连接失败独立于 Workspace 基线投影，并让 `startSession` 返回已结算的成功结果，因此外壳回调不会产生未处理的 Promise rejection。会话壳和 Workspace 浏览器会显示所保留的原始原因，并重试同一个 Workspace。浏览器还统一协调 fork、归档、恢复和持久化重排序操作；多个重叠操作的失败会依次保留，供用户逐一重试或关闭。真实 Workspace 中的 Session 拖拽只有在 Host 接受后才改变浏览器顺序，拒绝时会保留原顺序和准确的重试操作。

共用的 `Modal` 和 `Menu` 组件统一负责初始焦点、有序键盘移动、Escape 行为、嵌套界面的优先级、背景 inert 状态和焦点恢复。调用方只提供标签和初始焦点意图，不再自行建立 document 级键盘监听。

Lumi 桌面 bundle 为官方 DeepSeek 设置 namespace 注册带认证的模型发现。桌面端提交 DeepSeek 凭据时，会先用尚未保存的密钥请求所配置端点的 `/models`；只有请求成功后才会写入设置或凭据。不包含 Lumi 桌面 bundle 的浏览器部署仍使用普通的提供方保存流程，因为它没有桌面专用的发现能力所有者。

角色包导入会先检查来源，复制到暂存目录，验证暂存副本，再通过一次重命名完成安装。它绝不覆盖已经安装的包。失败的暂存数据会保留用于诊断，取消和验证失败都不会改变已安装目录。设置面板会显示 manifest 身份、作者、版本、许可证、目录诊断、导入进度和最终结果，不再把角色包根目录当作完整用户流程。

## 曾考虑的替代方案

**只把失败写入日志和开发者控制台。** 不予采用：发起操作的人无法判断操作仍在进行、已经被拒绝，还是可以安全重试；启动失败页还可能是当时唯一可用的界面。

**由每个弹窗和菜单各自处理焦点与 Escape。** 不予采用：嵌套覆盖层需要统一的顺序规则和焦点恢复所有者；彼此独立的 document 监听可能关闭错误的界面，或把焦点还给 inert 元素。

**先保存凭据，之后通过模型请求再验证。** 不予采用：探测失败会留下无法使用的密钥和提供方配置，把验证变成后续清理工作。

**让用户直接把角色包复制到正式目录。** 不予采用：复制中断和无效 manifest 会直接进入运行状态。暂存流程会在完整角色包通过运行时同一个读取器后，才改变已安装目录。

## 验证

聚焦的浏览器和 Host 测试覆盖恢复界面、键盘行为、可见的 Workspace 导航与操作重试、Host 确认后的重排序、偏好设置回滚、目录回退、角色包原子导入和写入前凭据验证。Windows 桌面 E2E 会启动组装后的应用，操作窗口控制和窄屏布局，终止 Harness，实际操作本地化失败页，重启 Harness，并确认主客户端重新出现。

## 后果

桌面失败会占用更多明确的界面状态，DeepSeek 凭据保存也会增加一次有界网络请求，但被拒绝的操作无需查看控制台就能被理解和恢复。Workspace 重排序会在 Host 接受后才改变已保存的浏览器顺序，因此慢请求期间会保留原顺序，而不是先呈现未经确认的结果。角色包升级需要将来单独制定策略，因为导入会明确拒绝覆盖。浏览器构建不依赖桌面专用 API 仍可使用，而外部提供方是否可用依然是运行时条件，不是发布保证。
