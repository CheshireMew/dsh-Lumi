# Agent Note：下游 DSH 补丁治理

状态：已实施

[English](2026-08-24-downstream-dsh-patch-governance.md) | 中文

## 问题

Lumi 优先使用增量插件和组合包 patch，但官方 DSH 的部分缺陷和缺失扩展点必须在本 fork 中修复，因为上游不接受所需改动。普通源码编辑会隐藏这项长期维护责任。既有上游同步清单只监视少量历史上容易冲突的文件，而当前 fork 已经同时包含有意保留的 DSH 改动和无法仅凭路径安全撤回或归属到单一功能的其它工作区改动。

## 决定

凡是存在于 `upstream-base` 的路径都属于上游。新建的 `@deepseek-ai/dsh-*` 包即使上游没有对应文件，也属于下游 DSH 改动。Lumi 专属行为继续优先使用 `@dsh-lumi/*` 插件、组合包、适配器和 profile patch。

`.upstream-patches.json` 把有明确语义的活动补丁与冻结的旧基线分开。活动补丁记录稳定 id、原因、负责的准确路径或显式递归目录、针对性验证、退役条件、已经复查到的官方提交和最近一次复查结果。初始旧基线为治理建立时无法安全归属的既有差异保存准确内容哈希。它会保留这些文件，但不会假装已经理解它们；任何内容变化都会使门禁失败，直到该路径升级为活动补丁，或在复查后被明确重新冻结。Vendored Cordis 仍由 `vendor/README.md` 管理，绝不进入这份清单。

`verify-upstream-patches` 将当前已提交内容和工作区状态与 `upstream-base` 比较。它会拒绝未登记的上游路径差异、已变化或陈旧的旧基线、无效补丁记录，以及在所记录复查提交之后被官方改动触及的活动补丁。上游同步报告会点名传入官方范围触及的每一项活动补丁。补丁记录人工复查结果之前，验证保持失败；复查结果必须是保留、重放、改接新扩展点或退役之一。

## 考虑过的替代方案

- **治理建立时撤回所有上游路径差异**——拒绝，因为脏工作区同时包含已经接受的 Lumi 基础、DSH 修复和其它进行中工作，无法只靠路径完成不会破坏内容的归属。
- **只依赖 Git 冲突和 `rerere`**——拒绝，因为自动文本合并可能不产生冲突，却保留已经失效的下游行为。
- **要求每项修复先得到上游 PR 接受**——拒绝，因为上游是否接受不受本 fork 控制，产品所需改动也没有这条可用路径。
- **只扩充 `.upstream.json.highConflictFiles`**——拒绝，因为扁平监视清单没有原因、验证、退役条件、复查提交，也不能为未分类差异保存准确冻结状态。

## 后果

本 fork 可以保留必要的 DSH 修复，不再把它们假装成普通 Lumi 代码，也不依赖上游接受 PR。无法分类的既有工作会被保留而不是破坏性撤回，但内容哈希冻结会阻止它们静默扩张。只有确实负责整个包级职责的补丁才使用整包选择器；仓库规则禁止把格式化、无关重构或 Lumi 专属行为混入这些补丁。

必需的所有权规则已经压缩到可执行约束。根说明原本已占用 1,900 词上限中的 1,885 词，因此文档上限提高到 2,000 词，而不是删除其它无关的项目规则。

上游合并仍然可能需要逐处判断源码。清单不会自动解决冲突；它会在接受新官方基线之前，明确展示受影响的本地决定、验证和退役条件。

## 验证

验证器通过单元测试覆盖准确路径、递归路径所有权和受影响补丁报告。它进入共享 CI 静态检查、仓库 hygiene 和受保护的上游同步检查。当前首次采用登记了七项活动补丁，其余当前受管差异全部按内容哈希冻结。
