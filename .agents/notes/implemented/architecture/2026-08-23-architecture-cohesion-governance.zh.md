# Agent Note: 架构内聚治理

Status: implemented

[English](2026-08-23-architecture-cohesion-governance.md) | 中文

## 问题

多个中心模块把彼此无关的策略、协议声明、状态转换与渲染集中在同一份实现中。Host API 实现还拥有其传输消费方使用的浏览器协议，形成了生产依赖环。客户端测试复制完整 API 替身，产品版本与视觉颜色存在多个所有者，可配置限额也直接嵌在运行时方法里。这些模式会让局部修改影响远处包，而且仓库无法在同类职责集中再次出现时自动报警。

## 决策

旧版浏览器协议归 `@deepseek-ai/dsh-api-protocol` 所有，位于 `dsh-client-connection` 与 `dsh-host-apiproxy` 的共同下层。Host 包实现该协议，但不再拥有协议。客户端包共享 `@deepseek-ai/dsh-client-api-testkit`，不再复制协议替身。公开产品名、版本、仓库身份、协议 token 与 HTTP user agent 统一来自 `@deepseek-ai/dsh-product-identity`。

`createApiProxy` 只负责组装。Session 运行时、读取、列表、摘要、交互、事件流以及各 API domain 分属独立模块。随部署变化的搜索、冷读取、游标保留与导出选项通过 `ApiProxyDefaults` 传入；已注册的设置命名空间在所有者处声明 `configuration-client` 可见性，不再写进网关列表。

Typert 分析将声明图构建、Remote 调用建模、Remote codec 建模以及 workspace／导出协调分开。Trajectory 表格拆分为 fold model、状态 hook、记录表、检查器、记录内容与检查器内容。目录浏览器和会话输入栏把状态及命令处理与渲染分离。Workspace 浏览器把排序和列表区段策略移出组装视图。

客户端颜色值由 `ui-theme` token 声明。组件消费语义或静态 token，包括插图填色与语法颜色，不再自行持有 RGB 或十六进制值。协议规定的 ANSI 颜色是唯一保留的运行时转换例外。

## 强制限制

`verify-architecture-governance` 会拒绝生产包依赖环、超过 1,000 行的新源文件、突破既有内聚模块或生成／数据型模块所记录上限的增长、六个已修复符号重新膨胀、生产代码中的 `0.0.1` 字面量，以及 `ui-theme` 之外的客户端颜色字面量。生成目录和测试支持源码不受普通源文件体积规则约束；显式列出的内聚模块仍有具名上限与保留原因。该门禁进入共享 CI 静态检查与仓库 hygiene。跨文件重复检测和客户端 domain 导入门禁继续独立运行，因为它们回答的是不同问题。

## 考虑过的替代方案

- **让 Host 包继续拥有协议，只用 type-only import 打破依赖环** —— 未采用，因为运行时 schema 和 carrier adapter 都是值，而且所有权仍会从较低的传输层指向较高的实现层。
- **只按文件大小拆分** —— 未采用，因为职责混杂的小文件仍具有相同耦合。拆出的模块必须拥有稳定职责，组装文件则依赖这些职责。
- **立刻让所有源文件服从同一个很小的上限** —— 未采用，因为生成目录、确定性 fixture 数据和内聚状态机会被任意切碎。通用上限约束新代码，现有例外则同时写明有限上限和职责理由。
- **允许组件局部保留颜色字面量** —— 未采用，因为局部字面量会静默绕过主题变化。主题 token 提供唯一且可审查的所有者，同时不要求每个视觉常量都随主题改变。

## 后果

生产依赖边上的包图保持无环，浏览器安全的协议消费方也不再加载 Host 实现的所有权。大型实现的审查和测试范围更小，但组装模块会导入更多具名协作者。结构门禁刻意保留一份很短的例外清单；新增或提高例外上限属于代码审查中可见的架构决策。新的视觉常量都需要主题 token，包括亮暗主题中保持同值的常量。

## 验证

治理脚本用单元测试覆盖依赖环检测、忽略注释的颜色检测与声明长度测量。它在仓库上检查真实包图、文件与符号上限、产品版本所有权和客户端源码。仓库重复检测不报告生产 clone。针对性的类型检查与行为测试覆盖 ApiProxy、Typert 生成、Trajectory 渲染、目录浏览、composer 输入和 Workspace 浏览。
