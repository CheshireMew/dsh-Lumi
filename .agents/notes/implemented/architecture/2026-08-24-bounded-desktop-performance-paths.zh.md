# Agent Note: 有界桌面性能路径

Status: implemented

[English](2026-08-24-bounded-desktop-performance-paths.md) | 中文

## 问题

桌面 Web 组合中有七条高基数路径，其工作量或保留状态缺少运行上限：Host 与浏览器事件队列、JSON 投影检查点重写、会话列表目录扫描、浏览器 Session 物化、Electron 诊断写入、侧边栏 DOM 行，以及工具结果参数查找。这些路径在会话历史较少时尚可接受，但普通的长期使用会让后台流量、重连、打开应用或渲染一个大型 Workspace 逐渐消耗更多延迟与内存。其中几条路径还隐藏了恢复行为：丢弃溢出的事件前缀或服务混合了不同分页代次的数据虽然快，却不正确。

会话事件日志仍是权威记录。派生索引、缓存、浏览器对象和已挂载行都可以被丢弃或重建，但性能上限不得静默移除持久历史、丢失已寻址的实时状态、混合分页代次，也不得改变 Workspace 排序与拖拽行为。

## 决策

1. Host 帧队列与浏览器解码后的 WebSocket 收件箱使用可配置的有界环形队列，出厂容量为 8,192 条消息。溢出会让整个 connection generation 失败并重连两条下行链路，由权威基线修复缺口。队列不使用数组头部移除。
2. Web 组合只把高频 `session_projcache` 存储域路由到 SQLite。每个检查点以行级 UPSERT 写入 `storages/session-projections.sqlite3`；其他存储域继续使用 JSON 后端。投影缓存仍由会话日志派生，因此已停用的旧 JSON 缓存无需迁移。
3. `session.list` 读取一个按真人直接 prompt 时间与 Session id 排序的持久 SQLite 索引。每页读取 `limit + 1` 条索引行，不物化持久化目录。第一页会为一代视图取得租约；短期行版本让后续页在 cursor 存活时间内保持不变，cursor TTL 过后清理过期代次与版本。正常关闭后，启动可以立即服务索引并在后台核对。新索引或上次非正常关闭时，会在进入就绪状态前完成核对。按精确 id 读取历史或恢复时使用持久化检查，不枚举目录。
4. 浏览器列表继续作为元数据投影。`SessionRuntime` 惰性物化 Session 对象与 agent scope，保护当前 Session 和被显式观察的 Session，并在超过配置的 8 个常驻上限时淘汰最近最少使用的非前台对象。淘汰会释放事件窗口、历史、投影与 scope 资源；仅存在于事件流中的待处理请求和队列快照继续按 Session id 保存，并为之后重建的实例提供初始状态。
5. Electron 主进程与 Harness 日志使用带背压的持久异步可写流。轮转保留一个有界当前文件和一个前序文件，在重命名前关闭 Windows 句柄，并在优雅关闭期间排空两条流。启动时的保留扫描仍采用同步方式，因为它是有界启动工作；稳定运行中的日志流量不会在主线程执行同步文件写入。
6. 分组与扁平侧边栏树在超过 80 个逻辑行时启用虚拟化。界面只挂载视口和预渲染范围，同时保留完整逻辑顺序，用于排序、无障碍位置元数据和 Workspace 拖拽命中测试。
7. 历史页在投影工具结果前，以一次正向遍历建立工具调用参数索引。因此工具结果查找与该页事件数量呈线性关系，不再反复扫描前面的区间。

## 考虑过的其他方案

- 提高队列容量或丢弃最旧帧没有采用。扩大容量只会延后无界增长造成的耗尽，静默丢失则让客户端状态无法核验。重连已经提供了修复路径。
- 把投影检查点继续留在共享 JSON 后端，只延长写入间隔没有采用。这样只能降低频率，仍保留整介质重写放大，还会增加冷回放工作量。
- 每次第一页请求都重建并排序完整会话目录，或保留完整内存快照数组没有采用。两者都会让启动与分页内存跟随会话总数增长。不保留版本的无状态 keyset cursor 也没有采用，因为页间变更会造成行跳过或重复。
- 让每个浏览器 Session 始终存活、只限制历史页大小没有采用。事件窗口、投影、订阅和 scope 仍会按访问过的会话持续累积。
- 对同步 Electron 写入做防抖没有采用。刷新时仍会阻塞主线程，也会让无丢失关闭更复杂。
- 渲染全部侧边栏行并依赖 CSS containment 没有采用。不可见 DOM 节点仍会产生 React、布局、无障碍树和内存成本。
- 没有为每次向后查找工具调用单独加缓存，而是建立一次明确的页级索引，使时间和内存上限便于检查。

## 后果

稳定运行时的事件与浏览器对象内存上限成为部署可见配置。事件过载现在会主动触发重连，因此调用方可能观察到一次恢复停顿，而不是内存无限增长。cursor 租约会暂时保留发生变化的会话索引行；其生命周期受 `sessionListSnapshotTtlMs` 限制，cursor 仍只在当前进程内有效。SQLite 会在用户普通 DSH 主目录下增加两个派生 Web 文件：会话列表索引和投影检查点数据库。两者都可以根据权威会话状态核对或重建。

侧边栏仍会对所有列表摘要计算逻辑分组和排序，但 React 与 DOM 物化量只跟随视口增长。受保护的当前 Session 或被观察 Session 可能暂时让常驻数量高于非前台上限；未受保护的对象会收敛到配置上限。桌面优雅关闭会等待诊断流完成，而进程异常终止时，异步文件沿用操作系统的一般持久性行为。

定向回归测试验证队列溢出与 FIFO 顺序、索引 `limit + 1` 分页与不可变代次、无需枚举目录的精确 id 查找、有界 Session 常驻与状态重建、异步日志轮转与背压、有界侧边栏 DOM 与完整逻辑基数、SQLite 投影组合，以及工具调用只解析一次。选择性运行的浏览器性能场景会分别记录侧边栏逻辑基数与挂载行数。
